## 初步认识 
简单来说：**MPU6050** 输出原始数据，通过**低通滤波/互补滤波/卡尔曼滤波/DMP** 这些不同的算法，计算出准确的**四元数**，再转换成直观的**欧拉角**，最后输入给 **PID 控制器**实现平稳控制。
### 1. 终极目标：欧拉角与四元数（表示姿态）
- **欧拉角 (Euler Angles)**：就是我们常说的航向角 (Yaw)、俯仰角 (Pitch)、翻滚角 (Roll)。它非常直观，控制系统（比如 PID）最终需要理解的就是欧拉角。
- **四元数 (Quaternion)**：由于欧拉角在特定角度（如俯仰角 $\pm90^\circ$）存在死锁（万向节死锁）问题，且计算三角函数很耗 CPU，所以在数学计算过程中，通常用四个数字表示的“四元数”来代替欧拉角。
- **关系**：**四元数是中间计算工具，欧拉角是最终展现结果。** 算法内部先算准四元数，再把四元数公式化转换成欧拉角。
### 2. 核心矛盾：陀螺仪与加速度计的缺陷
MPU6050 内部有加速度计（测线性加速度）和陀螺仪（测角速度）：
- **陀螺仪**：算姿态很快，但有**积分漂移**。时间一长，角度就会由于累积误差彻底“放飞自我”。
- **加速度计**：长期来看很准，但**怕震动**（高频噪声多）。平衡车一抖，它测出来的角度就满是噪声。
### 3. 解决办法：滤波算法与 DMP（数据融合）
为了扬长避短，把陀螺仪和加速度计的数据融合起来，就有了以下几种路线（**它们是并列或替代关系**）：
- **低通滤波 (Low-Pass Filter)**：最基础的滤噪。主要用来滤除加速度计的高频震动噪声，让数据变平滑。
- **互补滤波 (Complementary Filter)**：**性价比最高的方案**。
    - _原理_：对加速度计用低通滤波（要长期的趋势），对陀螺仪用高通滤波（要瞬时的动态），然后加权相加。
    - _公式_：$\text{角度} = 0.98 \times (\text{旧角度} + \text{陀螺仪积分}) + 0.02 \times \text{加速度计角度}$。
- **卡尔曼滤波 (Kalman Filter)**：**最精准的方案**。
    - _原理_：基于概率统计理论，结合系统的动态模型和测量噪声，进行最优状态估计。它能自动调节动态权重，效果比互补滤波更丝滑，但计算量大，非常消耗微控制器（如 Arduino/STM32）的算力。
- **DMP (Digital Motion Processor)**：**官方偷懒方案**。
    - _原理_：MPU6050 芯片内部自带了一个微型处理器。你把官方的固件（DMP 驱动）烧录进去，MPU6050 内部就会自己跑互补/卡尔曼类似的融合算法，直接通过 I2C 给你吐出**四元数**。
    - _优点_：完全不占用你单片机（MCU）的算力。

## 1. 互补滤波 (Complementary Filter)
互补滤波是最经典、高性价比的软件方案。它的核心思想是：**短期内相信陀螺仪（动态好），长期内相信加速度计（无漂移）**。
### 数学原理
1. **陀螺仪更新**：通过角速度积分得到角度。
    $θgyro=θlast+ω×Δt$
    （其中 ω 是陀螺仪角速度，Δt 是采样时间间隔）
2. **加速度计更新**：利用重力加速度分量直接计算三角函数得到角度。以俯仰角 (Pitch) 为例：
    $θacc=arctan2(Ay,Az)$
3. **互补融合**：
    $θfinal=α×(θlast+ω×Δt)+(1−α)×θacc$
    - α 通常取 `0.95 ~ 0.99`。例如 α=0.98，意味着 98% 相信陀螺仪积分，2% 引入加速度计修正。
### 代码实现 
``` c
// 假设 dt 为采样时间（如 0.005 秒，即 200Hz）
#define ALPHA 0.98f

float pitch = 0.0f; // 最终的欧拉角

void Complementary_Filter(float ax, float ay, float az, float gx, float gy, float gz, float dt) {
    // 1. 计算加速度计得到的 pitch 角（弧度转角度）
    // M_PI = 3.1415926
    float pitch_acc = atan2f(ay, az) * 180.0f / M_PI; 

    // 2. 陀螺仪角速度通常需要转换为度每秒 (°/s)，根据 MPU6050 量程配置
    // 假设 gx, gy, gz 已经是转换后的度每秒
    float pitch_gyro_rate = gx; 

    // 3. 互补滤波核心公式
    pitch = ALPHA * (pitch + pitch_gyro_rate * dt) + (1.0f - ALPHA) * pitch_acc;
}
```
## 2. 卡尔曼滤波 (Kalman Filter)
卡尔曼滤波在软件层面最精准。它分为预测（Update）**和**更新（Measure）两个阶段。这里以一维角度卡尔曼滤波为例（状态量包含：角度 θ 和陀螺仪零偏 b）。
### 数学原理
- **状态向量**：$X = \begin{bmatrix} \theta \\ b \end{bmatrix}$
- **状态预测（依据陀螺仪）**：$\theta^- = \theta_{last} + (\omega - b_{last}) \times \Delta t$
- **协方差预测**：预测当前的不确定度 $P^-$。
- **计算卡尔曼增益 K**：权衡预测模型和加速度计测量结果谁更可信。
- **状态更新（依据加速度计）**：$\theta = \theta^- + K \times (\theta_{acc} - \theta^-)$
- **协方差更新**：更新不确定度 P，为下一次循环做准备。
### 代码实现
``` c
// 卡尔曼状态变量结构体
typedef struct {
    float Q_angle;   // 过程噪声：角度噪声
    float Q_bias;    // 过程噪声：陀螺仪漂移噪声
    float R_measure; // 测量噪声：加速度计噪声
    float angle;     // 最终计算出的角度（欧拉角）
    float bias;      // 陀螺仪零偏
    float P[2][2];   // 误差协方差矩阵
} Kalman_t;

Kalman_t Kalman_Pitch = {0.001f, 0.003f, 0.03f, 0.0f, 0.0f, {{0,0},{0,0}}};

float Kalman_Filter_Update(Kalman_t* k, float acc_angle, float gyro_rate, float dt) {
    // 1. 预测阶段 (Predict)
    float rate = gyro_rate - k->bias;
    k->angle += rate * dt;

    // 更新误差协方差
    k->P[0][0] += dt * (dt * k->P[1][1] - k->P[0][1] - k->P[1][0] + k->Q_angle);
    k->P[0][1] -= dt * k->P[1][1];
    k->P[1][0] -= dt * k->P[1][1];
    k->P[1][1] += k->Q_bias * dt;

    // 2. 更新阶段 (Update)
    // 计算卡尔曼增益 K
    float S = k->P[0][0] + k->R_measure;
    float K[2];
    K[0] = k->P[0][0] / S;
    K[1] = k->P[1][0] / S;

    // 测量余量（测量值与预测值的差）
    float y = acc_angle - k->angle;

    // 更新状态估计（角度和零偏）
    k->angle += K[0] * y;
    k->bias  += K[1] * y;

    // 更新误差协方差矩阵
    float P00_temp = k->P[0][0];
    float P01_temp = k->P[0][1];

    k->P[0][0] -= K[0] * P00_temp;
    k->P[0][1] -= K[0] * P01_temp;
    k->P[1][0] -= K[1] * P00_temp;
    k->P[1][1] -= K[1] * P01_temp;

    return k->angle;
}

// 使用时调用：
// float acc_pitch = atan2f(ay, az) * 180.0f / M_PI;
// float final_pitch = Kalman_Filter_Update(&Kalman_Pitch, acc_pitch, gx, dt);
```
## 3. DMP (Digital Motion Processor) 硬件方案
DMP 并不是单片机上运行的算法代码，而是 MPU6050 内部自带的操作系统的硬解算。你需要将官方的一段固件（一串大数组二进制数据）通过 I2C 写入 MPU6050。
### 实现原理
1. **加载固件**：单片机初始化时，将 InvenSense 官方提供的 `inv_mpu.c` 和 `inv_mpu_dmp_motion_driver.c` 固件加载到 MPU6050 内部 RAM。
2. **芯片自计算**：MPU6050 内部的 DMP 硬件加速器以 200Hz 的频率在硬件层完成类似卡尔曼的融合计算，并将结果以**四元数 (Quaternion)** 的形式存在 FIFO 缓冲区中。
3. **单片机读取并转化**：单片机读取到 q0,q1,q2,q3 四元数后，通过数学公式在本地将其转换为欧拉角。
### 代码实现 (基于官方库的伪代码/流程)
``` c
#include "inv_mpu.h"
#include "inv_mpu_dmp_motion_driver.h"

float pitch, roll, yaw; // 最终想要的欧拉角

void DMP_Init(void) {
    mpu_init(NULL);                // 初始化MPU6050
    mpu_set_sensors(INV_XYZ_GYRO | INV_XYZ_ACCEL); // 开启陀螺仪和加速度计
    dmp_load_motion_driver_firmware(); // 【核心】将官方DMP固件烧录进芯片
    dmp_enable_feature(DMP_FEATURE_6X_LP_QUAT | DMP_FEATURE_ANDROID_ORIENT); // 开启六轴四元数功能
    dmp_set_fifo_rate(200);        // 设置DMP输出速率为200Hz
    mpu_set_dmp_state(1);          // 激活DMP
}

void Get_Euler_Angles(void) {
    short gyro[3], accel[3], sensors;
    unsigned char more;
    long quat[4]; // 用于存放接收到的四元数原始数据 (定点数)

    // 1. 从 FIFO 中读取四元数
    if (dmp_read_fifo(gyro, accel, quat, NULL, &sensors, &more) == 0) {
        if (sensors & INV_WXYZ_QUAT) {
            // 2. 将定点数四元数转换为浮点数 (缩放 2^30 次方)
            float q0 = (float)quat[0] / 1073741824.0f;
            float q1 = (float)quat[1] / 1073741824.0f;
            float q2 = (float)quat[2] / 1073741824.0f;
            float q3 = (float)quat[3] / 1073741824.0f;

            // 3. 【核心数学公式】四元数转欧拉角 (Pitch 和 Roll)
            // 这里利用了重力向量在机体坐标系下的投影关系
            float gravity_x = 2.0f * (q1 * q3 - q0 * q2);
            float gravity_y = 2.0f * (q0 * q1 + q2 * q3);
            float gravity_z = q0 * q0 - q1 * q1 - q2 * q2 + q3 * q3;

            // 最终转换为度数 (°)，这就是控制系统直接使用的欧拉角
            pitch = asinf(gravity_x) * 180.0f / M_PI;
            roll  = atan2f(gravity_y, gravity_z) * 180.0f / M_PI;
            yaw   = atan2f(2.0f * (q1 * q2 + q0 * q3), q0 * q0 + q1 * q1 - q2 * q2 - q3 * q3) * 180.0f / M_PI;
        }
    }
}
```
## 核心区别与选择
1. **互补滤波**：最轻量。只有 3 行公式，不需要复杂库，执行耗时极低（微秒级），适合资源极度匮乏的单片机。
2. **卡尔曼滤波**：最平滑。对突发的震动抑制效果最好，但单片机需要连续计算几十行浮点矩阵，代码量和运算开销较大。
3. **DMP**：最省心。算法在 MPU6050 硬件内部跑，单片机只要通过 I2C 读现成的四元数，然后运行最后的“四元数转欧拉角公式”即可。缺点是官方驱动库代码很重。
## 算法拓展
**互补滤波和卡尔曼滤波在处理一维或二维姿态（比如只有 Pitch 和 Roll）时，完全可以直接输出欧拉角，根本不需要四元数。**

**Mahony 算法是“使用四元数的互补滤波”，而 Madgwick 算法则是一种“使用四元数的、高度优化和变种的卡尔曼/梯度下降思想滤波”**
## 1. Mahony 算法：四元数 + 互补滤波
Mahony 算法是目前四轴无人机（如 Betaflight 飞控）中应用最广泛的算法之一。它的核心逻辑和一维互补滤波一模一样，只不过全部升级到了**三维向量和四元数**空间。
### 它是怎么“互补”的？
- **谁代表陀螺仪（高频动态）**：算法维护一个**四元数 $q$**。每次循环，直接用陀螺仪测出的角速度（$\omega_x, \omega_y, \omega_z$）去更新这个四元数。
- **谁代表加速度计（长期准确）**：当前四元数 $q$ 可以理论推算出“我认为的重力向量应该指向哪里”（理论重力向量 $v$）。而加速度计实际测出了“真正的重力向量在哪里”（测量重力向量 $a$）。
- **融合（叉积误差修正）**：
    - 算法计算这两个重力向量的**叉积（Cross Product）**：$e = a \times v$。这个叉积 $e$ 完美反映了理论姿态和实际姿态之间的**角度偏差**。
    - 既然有了偏差，那就用 **PI（比例积分）控制器** 把这个误差 $e$ 乘以一个系数，**直接加到陀螺仪的角速度上**去修正它！
    - 修正后的角速度再去更新四元数。
> **总结**：它用加速度计的误差去实时“校准”陀螺仪的角速度，然后用校准后的角速度积分得到四元数。这就是三维空间的互补滤波。
## 2. Madgwick 算法：四元数 + 梯度下降（平替卡尔曼）
Madgwick 算法在很多 IMU 姿态传感器模块中非常流行。很多人误以为它是卡尔曼滤波，**严格来说它不是卡尔曼，但它达到了类似卡尔曼的抗噪效果，且计算量远小于卡尔曼**。
### 它是怎么实现的？
标准卡尔曼滤波在三维空间（考虑 4 个四元数状态 + 3 个陀螺仪零偏 = 7维矩阵）中需要进行极其恐怖的**大矩阵求逆运算**，普通的单片机（如 STM32F1）根本跑不动。
Madgwick 博士想出了一个天才的替代方案——**梯度下降法 (Gradient Descent)**：
1. **方向预测**：同样，先用陀螺仪角速度积分更新四元数。
2. **误差最优化（梯度下降）**：把加速度计（和磁力计）的测量值看作是一个“目标函数”。现在的四元数和目标函数之间有误差，算法不进行复杂的矩阵预测，而是沿着误差变小的方向“跨出最优的一步”（求导数、走梯度）。
3. **加权融合**：将陀螺仪计算出的四元数变化率，与梯度下降方向算出的四元数变化率，进行**线性加权融合**。
> **总结**：它用极其高效的“梯度下降”数学技巧，代替了卡尔曼滤波中沉重的“矩阵方差计算”，既有卡尔曼对高频噪声的强力抑制，又跑得飞快。

## 1. MPU6050_Get_Angle —— 基础动态互补滤波（2D 空间）
这个函数对应的是**普通互补滤波**，并加入了**动态权重调整**。它在解算时避开了四元数，直接用三角函数去算 Roll 和 Pitch。
### 核心算法步骤：
1. **原始数据低通滤波（前置处理）**：
    在函数一进来的 `MPU6050_Get_Raw(this)` 中，源码通过宏定义 `#if MPU6050_USE_Filter` 开启了前置滤波。它调用了 `PT1Filter_Apply`（你上传的 `filter.c` 中的 **一阶低通滤波器**），分别对加速度计和陀螺仪的原始 6 轴数据进行了平滑去噪。
2. **计算自适应权重 (`weight`)**：
    ``` c
    float absAcc = sqrt(Ax * Ax + Ay * Ay + Az * Az);
    if (absAcc > 1.2) { weight = 0.8f; } // 剧烈震动，减小加速度计权重
    else { weight = 0.98f; }             // 静止或平稳，强烈信任加速度计
    ```
    代码计算了当前加速度的模长（正常静止时接近 1.0g）。当发生剧烈震动导致模长超过 `1.2g` 时，降低加速度计在互补滤波中的权重（从 `0.98` 降到 `0.8`），从而完美抑制了加速度计“怕震动”的缺陷。
3. **一维互补解算欧拉角**：
    以 Roll 为例：
    ``` c
    this->roll = weight * atan2(Ay, Az) / 3.1415926f * 180.f + (1 - weight) * Gyroscope_roll;
    ```
    - `atan2(Ay, Az)` 是通过加速度计直接算出的欧拉角。
    - `Gyroscope_roll` 是陀螺仪角速度积分出来的欧拉角。
    - 它们通过 `weight` 进行加权互补，直接输出欧拉角。
> **缺陷**：由于它是单独对 Roll 和 Pitch 进行一维独立解算，无法处理三维空间重力向量的耦合，且它的 `yaw` 轴只是单纯对 `Gz` 进行积分，没有任何校正，**时间一长 Yaw 轴必然会严重漂移**。
## 2. MPU6050_Get_Angle_Plus —— 自适应 Mahony 磁力计缺失版算法（3D 全姿态）
这个高级函数用的是大名鼎鼎的 **Mahony 互补滤波算法**（注释里写的 Madgwick 其实是误称，从数学源码看它是纯正的 Mahony 算法），并且加入了**自适应动态增益（Adaptive Gain）**。
### 核心算法步骤：
1. **自适应调节 PI 控制器参数 (`Kp`, `Ki`)**：
    ``` c
    // 正常重力范围内(0.8G ~ 1.2G 之间，对应平方后 0.64 ~ 1.44)
    Kp = (accMag > 1.44f || accMag < 0.64f) ? 3.6f : 4.8f;
    ```
    根据当前总加速度是否处于重力异常区，动态调整 Mahony 算法的比例增益 $K_p$。如果震动大，就减小 $K_p$（减少对加速度计的信任）。
2. **计算重力方向误差（叉积）—— 算法灵魂**：
    ```
    // 1. 用当前四元数推算理论上的重力向量 v (vx, vy, vz)
    float vx = 2.0f * (q1 * q3 - q0 * q2); ...
    // 2. 将实际测得的加速度(ax, ay, az)与理论重力向量求叉积，得到误差 Vector e
    float ex = ay * vz - az * vy; ...
    ```
    这里完美展现了 Mahony 算法的精髓：它不直接把加速度转成角度，而是用**四元数推算的重力方向**与**加速度计测得的重力方向**做**三维叉积**。叉积结果 `ex, ey, ez` 完美代表了姿态的整体误差。
3. **PI 反馈校正陀螺仪**：
    ``` c
    integralX += ex * mpu6050_dt; // 积分项
    gx += Kp * ex + Ki * integralX; // 将误差反馈并叠加到陀螺仪角速度上，强制校正漂移
    ```
4. **四元数一阶龙格-库塔更新与归一化**：
    用校正后的角速度更新四元数状态，并通过 `invSqrt`（源码里使用了雷神之锤中著名的 **快速平方根倒数算法**，用来压榨单片机浮点开销）将四元数归一化。
5. **四元数转欧拉角 & Yaw轴解包裹（Unwrap）**：
    ``` c
    this->roll  = atan2f(2.0f * (q0 * q1 + q2 * q3), 1.0f - 2.0f * (q1 * q1 + q2 * q2)) * 57.29578f;
    this->pitch = asinf(2.0f * (q0 * q2 - q3 * q1)) * 57.29578f;
    ```
    在全姿态空间完成融合滤波后，最后通过公式将四元数脱壳，转换为用户需要的直观欧拉角。源码在最后还贴心地对 `yaw` 进行了防止 $\pm180^\circ$ 发生突变跳变的“解包裹”处理。
## 总结
- 跑 **`Plus` 函数（自适应 Mahony 算法）** 的效果已经极其丝滑，通过四元数叉积反馈控制，不仅能实现全姿态抗万向节死锁，运算速度还远快于高维卡尔曼滤波。
- 跑 **`Normal` 函数（带有低通滤波+一维互补）**，对于平衡小车而言，算力开销极小且动态响应快，性价比最高。
